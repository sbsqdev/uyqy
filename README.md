# Charter Key — платформа для гоночных программ

Двуязычный демо-продукт (EN/RU): места в экипаже гоночной яхты, календарь событий,
академия, клубная подписка, карта города и два ИИ-помощника. Не привязан к стране:
акватории, лодки и цены — подставляемые данные, а не часть кода.

Демо едет с четырьмя акваториями: **Аннаполис** (Чесапикский залив), **Ньюпорт** (Род-Айленд),
**Сан-Франциско** (залив), **Майами** (Бискейн). По 9 мест на карте в каждой, 9 событий сезона.

## Кому показывать

Страница работает в двух ролях одновременно:

* **Яхтсмену** — это готовый продукт: выбрал акваторию, прошёл подбор тарифа, забронировал место,
  спросил ассистента про документы и гида про ужин после гонки.
* **Клубу или гоночной программе** — это витрина платформы. Секция «This whole page is the product»
  объясняет, что воронка, ассистенты и аккаунт переносятся на их лодки и даты.

## Два языка

Переключатель EN/RU в шапке. По умолчанию английский; при первом заходе язык определяется
по браузеру (кириллические локали → русский). Выбор сохраняется в `localStorage`.

* Контент в `data.js` хранится как `{ en, ru }`, читается хелпером `T(field)`.
* Строки интерфейса — в `assets/js/i18n.js`, читаются как `t('hero.ctaCal')` или `t('poi.pts', { n: 40 })`.
* История в аккаунте хранит ключ события и параметры, поэтому переписывается при смене языка целиком.
* У мест два набора тегов: `tags` (английские, внутренние ключи для подборок и ИИ) и `tagsRu` — для показа и поиска по русским запросам.


## Как добавить акваторию

В `DESTINATIONS` (`assets/js/data.js`) — объект с метаданными, картой и местами:

```js
{
  id: 'charleston', flag: '🇺🇸',
  city:   { en: 'Charleston', ru: 'Чарлстон' },
  region: { en: 'South Carolina · The Harbour', ru: 'Южная Каролина · гавань' },
  blurb: {...}, season: {...}, wind: {...}, water: {...}, airport: {...}, travel: {...},
  accent: '#3ddad7',
  map: { viewBox: '0 0 1000 620', land: [...], islands: [...], route: '...', labels: [...] },
  points: [ /* место: id, cat, x, y, pts, name, price, time, desc, tip, tags, tagsRu */ ]
}
```

* `cat` — `eat` / `see` / `do` / `night` / `yacht`
* `x`, `y` — проценты от ширины и высоты карты
* `land` и `islands` — SVG-пути береговой линии в системе координат `viewBox`
* события привязываются к акватории полем `city` в `REGATTAS`

Всё остальное — тарифы, курсы, клуб, квиз, FAQ, награды — правится там же, без кода.

## Живые ИИ вместо офлайн-движков

Оба помощника работают локально: разбирают намерение и отвечают из данных — предсказуемо,
без ключей и бэкенда. Чтобы подключить настоящую модель, замените вызов `engine().answer()`
в `assets/js/app.js` на запрос к своему бэкенду:

```js
const res = await fetch('/api/ai', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ query: text, mode, venue: state.venue, lang: Lang.get(), profile: state })
});
```

На сервере — Claude (`claude-opus-5`), два system-промпта под `mode`: `assistant` получает правила
тарифов, безопасности и баланс аккаунта, `guide` — места выбранной акватории. Язык передавайте
в запросе и просите отвечать на нём же. Ответ в формате `{ text, cards, chips }` — его интерфейс
уже умеет рисовать. Ключ API держите на сервере.

Движки не зависят от DOM, поэтому переносятся в Telegram-бота без изменений.

## Данные и хранение

Аккаунт, очки, чек-ины, брони, курсы и подписка лежат в `localStorage` — демо без сервера.
Оплаты имитируются: «Buy $149», «Join the club» и «Book a walkthrough» показывают тост.
Кнопка «Reset progress» стирает всё.

Контент демонстрационный: цены, условия, остатки мест и названия заведений вымышлены.
Перед показом реальным клиентам заменить в первую очередь условия отмены, состав тарифов
и заявления о безопасности.
